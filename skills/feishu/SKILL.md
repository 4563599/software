# 飞书

使用 `scripts/feishu_docs.py` 通过用户身份访问飞书个人云盘。支持创建、追加和替换新版文档正文，不添加协作者、不更改共享范围，也不删除文档本身。

## 本机配置

- 在每台电脑上分别配置飞书自建应用的 App ID 和 App Secret；不要把它们、用户令牌或私人文档链接提交到仓库。
- OAuth 回调地址默认是 `http://localhost:53682/callback`，必须与飞书开放平台配置一致。
- 必需的用户权限：`docx:document`、`docs:document.media:upload`。

## GitHub 同步

- 本机此 Skill 有功能或说明更新时，在同一任务中将对应的脱敏版本同步到私有仓库 `https://github.com/4563599/software.git` 的 `skills/feishu/`，并验证推送结果；没有实质差异时不创建提交。
- 仓库副本是可移植版本。只同步 Skill 源文件，保留本机专用配置在本机；不得直接将本目录整体复制或推送到仓库，也不得用仓库副本覆盖本机配置。
- 提交前检查暂存差异，排除 App ID、App Secret、令牌、真实账号密码、私人飞书链接及本机缓存。无法确定内容是否安全时停止推送并告知用户。

## API 优先

- 创建文档、读取文档信息、写入正文、追加正文、替换正文和检查结果，必须优先使用 `scripts/feishu_docs.py` 调用飞书 Open API。只要 API 能完成，就不得使用内置浏览器或桌面自动化模拟点击、输入和复制粘贴。
- 内置浏览器只用于必须由用户交互完成的授权步骤，例如 OAuth 登录、权限确认，或首次配置时在尚未取得 API 访问权限前获取必要凭证。授权完成后立即回到 API 流程，不继续通过页面操作文档内容。
- API 返回权限不足、能力不支持或接口错误时，先报告错误码并检查权限、参数和接口能力；不得未经用户同意自动降级为浏览器模拟操作。
- 只有确认 Open API 无法完成目标、并且用户明确同意后，才可以使用浏览器处理那个无法由 API 完成的具体步骤。不要把浏览器作为 API 的常规备用方案。
- 浏览器授权操作不得读取、记录或回显 OAuth code、访问令牌、刷新令牌和 App Secret；脚本仍负责校验授权状态并保存令牌。

## 工作流程

1. 先确认上传位置。用户没有明确提供目标文件夹或文档时，必须先暂停并只询问一个简短问题：“请告诉我上传到哪个飞书文件夹或文档，可以提供名称或链接。”在用户回答之前，不整理内容、不检查源码、不调用写入接口。用户已经明确给出位置时视为已回答，不要重复询问。
   - 创建文档需要目标文件夹名称、URL 或 `folder_token`。
   - 追加内容需要目标文档 URL 或 ID。
2. 确认要写入的内容和文档标题。用户说“上传上面的回答”时，直接复用当前对话中已有答案，不重新检查项目、联网研究或扩写，除非用户明确要求更新内容。新建文档的正文不要重复写与飞书文档标题相同的一级标题；正文通常从二级标题开始。
3. 用户尚未完成授权或脚本提示缺少配置时，必须读取 `references/setup.md`，然后完成当前电脑的独立授权。Windows 上安全输入 App ID 和 App Secret 并保存本机配置：

   ```bash
   python scripts/feishu_docs.py configure
   ```

   再运行一次式 OAuth：

   ```bash
   python scripts/feishu_docs.py authorize --open-browser
   ```

   授权完成后使用下列命令确认访问令牌与刷新令牌均已保存，并且绑定当前电脑、包含必需权限。输出只能包含状态，不能包含令牌值：

   ```bash
   python scripts/feishu_docs.py status
   ```

   只有 `token_bound_to_current_device`、`required_oauth_scopes_satisfied`、`access_token_valid` 和 `refresh_token_valid` 全部为 `true`，才允许继续执行文档操作。否则必须停止并重新授权。只有本地回调不可用时，才退回 `auth-url` + `exchange-code` 手工流程。
4. 写入前先使用 `--dry-run` 核对目标、标题、内容长度以及标题、列表、代码块和 Mermaid 图片数量。用户当前请求已经清楚指定目标和内容时，该请求本身即为写入授权；否则先询问。
5. 创建新文档：

   ```bash
   python scripts/feishu_docs.py create --title "文档标题" --content-file "content.md"
   ```

   如需放入指定个人文件夹，添加 `--folder <文件夹URL或folder_token>`。

6. 追加到已有文档：

   ```bash
   python scripts/feishu_docs.py append --document "https://example.feishu.cn/docx/文档ID" --content-file "content.md"
   ```

7. 替换已有文档的全部正文：先执行预览，再带确认参数执行正式替换。`replace` 保留文档 ID、标题、位置和链接，只替换根节点下的正文块。

   ```bash
   python scripts/feishu_docs.py replace --document "https://example.feishu.cn/docx/文档ID" --content-file "content.md" --dry-run
   python scripts/feishu_docs.py replace --document "https://example.feishu.cn/docx/文档ID" --content-file "content.md" --confirm-replace
   ```

   `replace` 会先完整追加并校验新正文，再从后向前删除旧正文，最后再次校验块数量。写入新正文失败时不删除旧正文；中途失败后可在核对文档后重新执行同一命令，使文档最终只保留一份新正文。用户只要求“追加”时不得改用 `replace`。

8. 检查文档是否可访问以及根块数量：

   ```bash
   python scripts/feishu_docs.py check --document "文档URL或ID"
   ```

9. 用户明确要求把真实凭证写入指定私人文档时，先说明在线文档的共享和历史版本风险；确认后使用安全输入直接写入，凭证不得出现在聊天、命令行参数或执行日志：

   ```bash
   python scripts/feishu_docs.py write-credentials --document "文档URL或ID" --confirm-sensitive-upload
   ```

10. 成功后向用户返回文档链接、写入块数和目标位置；失败时报告飞书错误码和解决办法。无论是否允许写入目标文档，都不得在执行输出中显示访问令牌、App Secret 或刷新令牌。

## 快速上传

- 目标、标题和内容都明确后，只执行必要流程：`status`、生成临时 UTF-8 Markdown、对应的 `create/append/replace --dry-run`、正式写入、`check`。
- 不为寻找已知位置扫描整个文件系统或历史任务。未知的文件夹只有名称、没有已配置别名时，直接向用户索取文件夹链接。
- 不重复分析已经完成的回答。优先原样复用内容，只做飞书格式转换。
- 上传用的临时内容文件在成功校验后删除，不在项目仓库留下文件。

## 飞书电子表格

- 读取本地 Excel 后，默认通过 Sheets Open API 创建原生飞书电子表格，不上传源文件，不使用浏览器模拟填写。
- 写入后必须根据每列实际内容调整列宽，不能保留会截断文字的默认列宽。
- 计算显示长度时，中日韩及全角字符按 2 个显示单位计算，英文、数字和半角符号按 1 个显示单位计算。
- 12pt 字体下，每个显示单位至少按 8 像素计算。
- 列宽计算公式：`最大显示单位数 × 8 + 48像素留白`。
- 列宽最小为 88 像素，最大可限制为 1000 像素。
- 字号大于 12pt 时，字符宽度需要按比例增加。
- 长内容优先开启自动换行，并根据换行数量增加行高。
- 如果飞书 API 不支持设置自动换行，则必须扩大列宽，直到内容完整显示。
- 不得为了压缩表格宽度而截断标题、股票名称、涨跌幅或标签。
- 完成前必须通过 API 回读全部单元格，核对数据是否完整。

### 账号密码表

- 本小节及 `feishu_credentials_sheet.py` 仅用于用户明确要求的账号密码表；普通飞书文档和电子表格不套用下述三列结构、分组、颜色或居中样式。
- 用户选定的样式是“标题、账户、密码”三列：同一工作表可以有多个标题小组；换到新小组时先留一行空白，同一小组的连续记录在 A 列纵向合并。使用方案 3 的紫色表头、浅紫色分组底色；所有单元格水平和垂直居中，分组标题统一为黑色 12pt 粗体。可在同一工作簿按需增加多个工作表；每张表均保留相同的三列。创建第一张表时，工作簿标题、工作表名和 A 列标题可由用户分别指定。
- 真实凭证写入前，先告知飞书共享权限和版本历史中的明文风险，取得用户确认，并核对目标文件夹或表格 URL。不得把账号或密码写进命令行参数、临时文件、日志、技能文件或最终回复；使用脚本的隐藏交互提示输入。用户此前已在聊天中发送凭证时，不要再次回显。
- 新建工作簿并录入一条：`python scripts/feishu_credentials_sheet.py --folder <文件夹URL> --title <工作簿名> --sheet <工作表名> --group-title <A列标题>`。
- 向已有工作簿增加记录或工作表：`python scripts/feishu_credentials_sheet.py --spreadsheet <表格URL> --sheet <工作表名> --group-title <A列标题>`。脚本会检查三列表头、调整列宽和行高、按标题合并，并统一已用区域的居中对齐及全部分组标题样式，再回读确认账号与密码；输出只包含表格链接、工作表、行号及校验状态。
- 创建前确认目标文件夹，避免同名文件；追加前确认是用户指定的已有表格。不要自动修改共享权限或把凭证复制到其他文档。

## 安全边界

- 个人云盘操作优先使用 `user_access_token`，不要用应用身份冒充用户创建私人文档。
- OAuth 必须校验随机 `state`，避免接受不属于本次授权的回调。
- 用户访问令牌和刷新令牌只保存到当前用户的 `~/.codex/feishu/token.json`；缓存文件不得加入 Skill 安装包或 Git。
- 令牌缓存必须绑定生成它的电脑和系统用户。不得把 `token.json` 复制到另一台电脑；脚本检测到设备不匹配时必须拒绝访问。
- 每台电脑都必须单独执行 `configure` 和 `authorize`。不得用环境变量直接注入用户访问令牌来绕过 OAuth。
- 不在终端、聊天、日志或最终回复中显示令牌内容；验证授权时使用 `status` 命令查看布尔状态和有效期。
- 不把真实凭证硬编码进 Skill、项目或 Git，也不在普通命令行参数中传递凭证值。
- 只有用户明确提出把真实凭证写入指定文档或电子表格，了解明文共享与历史版本风险并确认后，才允许执行敏感写入；目标不明确时必须停止并询问。
- 敏感值只从安全交互输入或专用本机环境变量读取，直接写入目标文档，不在预览、标准输出、错误日志和最终回复中回显。
- 敏感文档写入后提醒用户检查分享范围；Skill 不自动添加协作者。
- 新文档继承用户个人云盘/目标文件夹的共享策略。脚本不会主动公开文档，但“仅自己可见”仍应在飞书分享设置中核对。
- 删除文档、移动文档、修改共享权限等操作不在本 Skill 范围内。`replace` 只在用户明确要求更新或替换指定文档时删除其旧正文，而且必须先预览并使用 `--confirm-replace`。

## 内容处理

- 支持 `--content`、`--content-file` 或 `--stdin`，三者只能选择一个。
- 上传前先整理清晰层级：飞书文档名称承担总标题；正文优先使用二级标题划分主要部分、三级标题划分子部分，避免整篇只有普通段落。
- Markdown 的 `#` 到 `######` 会转换为飞书原生一至六级标题，标记符号本身不会显示。
- Markdown 的 `-`、`*`、`+` 无序列表和 `1.`、`1)` 有序列表会转换为飞书原生列表。
- 标准 Markdown 表格必须转换为飞书原生表格块，不得把 `|`、`---` 和整行 Markdown 表格语法作为普通文本上传。表格第一行作为加粗表头；单元格中的反引号内容转换为行内代码样式。
- 文档原生表格按内容自动设置列宽：中日韩及全角字符按 2 个显示单位、英文数字按 1 个显示单位计算；每个显示单位按 8 像素并增加 48 像素留白，单列宽度限制在 88～480 像素，整表宽度原则上不超过 900 像素。
- 字节、字符、枚举等短值对照如果超过 8 项，不要使用“每项一行”的狭长两列表格。优先把 2～4 组“值/含义”横向排列在同一行；例如 16 个“十六进制/字符”映射使用 4 组并排的 5 行 × 8 列表格，减少纵向留白，同时保持从左到右、从上到下的原始顺序。
- 创建原生表格后必须通过 API 回读表格块，确认行列数对应的单元格 ID 数量完整；写入失败时删除本次产生的空表格，不能留下加载中或无内容的占位表格。
- 普通段落保持为飞书文本块。当前版本不转换粗体、斜体和行内代码样式，因此不要依赖这些样式表达关键层级。
- 内容中只要包含代码，就必须使用三个反引号组成的 Markdown 围栏代码块；开头可在三个反引号后标注 `kotlin`、`java` 等语言，也可以不标注。不要把多行代码作为普通段落提交。
- 脚本会把围栏代码转换为飞书原生代码块（`Code Block`），并保留代码的缩进、空行和换行；围栏本身及语言标记不会写入代码正文。
- 语言标记为 `mermaid` 的围栏代码块是特殊情况：脚本必须先在本地把 Mermaid 渲染为 PNG，再通过飞书图片块 API 上传。不得把 Mermaid 源码单独作为普通代码块来冒充已经生成的流程图，也不得把文档内容发送到第三方在线渲染服务。
- 每个 Mermaid 流程图在飞书中的固定顺序为“图片块 → 原始 Mermaid 代码块”。源码必须紧跟在对应图片下方，保留完整缩进和换行，便于用户以后复制、修改和重新生成流程图。
- 图片块创建后必须上传媒体，并调用 `replace_image` 写入返回的 `file_token`、真实宽度和真实高度。完成前通过 API 回读图片块，确认 `image.token` 非空且 `width`、`height` 均大于 0；仅检查 `block_type=27` 不算成功。
- Mermaid 渲染依赖本机 Node.js、Chrome/Edge/Chromium，以及 `mmdc` 或可运行 Mermaid CLI 的 `npx`。缺少依赖或语法错误时必须停止并报告明确原因，不得静默退化为只有源码、空白图片或一直加载的占位块。可用 `MERMAID_BROWSER_PATH` 指定浏览器可执行文件。
- 行内反引号代码仍作为普通文本写入。围栏未闭合时按普通文本处理，避免误判或吞掉内容。
- `--dry-run` 会返回 `planned_heading_blocks`、`planned_list_blocks`、`planned_code_blocks`、`planned_mermaid_images`、`planned_table_blocks` 和 `planned_table_cells`。一个 Mermaid 围栏应同时增加一个 Mermaid 图片和一个源码代码块；每张 Markdown 表格应增加一个原生表格块，写入前必须确认数量与预期一致。
- 长内容会自动分段、分批写入，并控制请求间隔以避开单文档编辑频率限制。

## 同时生成 Excel 文件

- 当用户的飞书任务还要求生成 `.xlsx` 文件时，使用可用的表格 Skill 创建并验证工作簿；`feishu_docs.py` 仍只负责飞书新版文档，不要把 Excel 内容伪装成文档正文。
- 所有已填充单元格的文字和数值必须完整可见，不得出现文字截断、`#####`、被相邻单元格遮挡或行高不足。
- 根据实际内容调整列宽和行高。短内容优先适度加宽列；长文本启用自动换行，并增加行高直到全部文字可见，同时限制过宽列，避免工作表横向失控。
- 单元格内容与边缘应保留轻微间隙。Excel 没有通用的内边距属性时，通过适度增加列宽、行高，并在适合的文本列使用一级缩进实现；不要用前后空格伪造间隙，以免污染真实数据。
- 表头和正文保持合适的垂直对齐，正文文本通常左对齐，数值按语义右对齐。现有模板或用户明确指定的格式优先。
- 导出前必须渲染并检查所有工作表，重点确认长标题、说明文字、代码、URL、日期和数字均完整显示；发现裁切后修正列宽、自动换行或行高，再重新验证。
