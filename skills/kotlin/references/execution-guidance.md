# 额外执行说明（非网页规范原文）

本文件是将编码规范用于实际项目时的执行策略，不是指定网页的原文或新增的官方规范。
网页规则只见 [编码规范正文](coding-conventions.md)。报告问题时，应区分“网页规范”“项目约定”和“执行建议”。

## 任务与修改边界

- 先确认用户要求是生成、修改、审查还是解释。审查或解释不自动授权修改源代码。
- 查看适用的 `AGENTS.md`、`.editorconfig`、格式化与静态检查配置、项目版本和相邻代码风格。
- 用户明确要求和项目明文约定优先；与网页有差异时说明差异，不静默修改全项目规则。
- 新代码遵循适用规范；已有代码采用最小必要修改，不顺带迁移架构、移动源目录或重排无关文件。
- 不自动修改用户 IDE 的全局配置，不因网页列出了配置路径就替用户应用设置。
- 本技能不自动安装到全局目录，不覆盖另一个 `kt` 技能，也不修改其他技能。

## 兼容性与语义保护

- 不为使用较新语法自动升级 Kotlin、Gradle、AGP 或依赖。先检查目标版本是否支持 `..<`、`when` 守卫等写法。
- 重命名公有 API、修改可空性、默认参数、构造函数、重载、返回类型和可变性可能改变契约，不能视作纯排版。
- Java 方法不能直接使用 Kotlin 具名实参；将网页建议应用于 Java 互操作时先检查调用限制。
- 只读集合接口不等于深度不可变或线程安全，不以改成 `List` 的方式声称解决并发问题。
- 改写 Lambda 时保持 `return`、`return@label` 和匿名函数的退出目标，合法的提前退出不是一律禁止。
- 可空布尔值的 `value != true` 包括 `false` 与 `null`，不能机械替换为 `value == false`。
- 表达式体、`trimIndent`、`trimMargin` 和作用域函数的改写要保留计算顺序、实际返回值及文本空白。
- 不为了代码更短堆叠作用域函数、扩展函数或集合链；兼顾可读性、分配开销及原有行为。
- 平台类型的显式 Kotlin 类型应符合实际空值契约，不为消除平台类型盲目添加 `!!`。

## 项目个人约定

- 固定作者名、创建时间、中文类头模板、Android 文案策略和字符串资源复用，不是该网页的要求。
- 用户或项目另有这些约定时照常执行，但必须明确它们来自项目，不并入网页规则正文。
- 文档中的示例是说明某条规则的片段，不等同于可直接运行的完整应用；不要为示例占位上下文引入生产依赖。

## 项目附加规则（用户要求）

以下三项是用户明确要求的项目约定，不是网页规范原文。涉及对应工作时执行。

### 1. 测试完成后清理临时测试代码

- “需要删除的测试代码”限定为本次为了验证而临时增加的模拟数据、硬编码状态或版本号、测试入口、临时页面、临时开关、调试日志和辅助文件；正式单元测试、回归测试及其必要 fixture 不因名称含 test/mock 而删除。
- 测试确实完成、准备正式交付时，清理本次临时内容并恢复真实数据与正常执行路径，包括位于 Debug 分支中的临时模拟。
- 用户仍需查看模拟效果、验证尚未完成或明确要求暂时保留时，不提前删除；交付说明中指出尚保留的临时内容和清理时机，不宣称已经清理完成。
- 依据本次修改记录确认归属，只删除本次新增的临时内容。已有测试、日志或用户代码不擅自删除；无法确认归属时先说明并确认。
- 删除临时入口或文件时同步清理本次新增、已无引用的导入、资源与配置；不顺带清理无关资源，不把临时测试文件或日志加入 Git 提交。
- 清理后按改动风险重新编译或运行关键检查，确认没有残留假数据、未解析引用或因删除产生的编译错误。

### 2. 资源先检索，匹配时优先复用

- 新增资源或硬编码资源值前，先检索项目现有资源及可直接引用的共享模块；使用 `rg` 等工具按内容、资源名和现有引用查找，不能只因没找到预期 key 名就新建。
- 检索范围按当前项目包括字符串、plurals/数组、drawable/mipmap 图片图标、dimen 宽高/间距/圆角/字号、color、style 及主题属性等。检查相关 `values*`、密度、夜间模式和其他限定版本是否适合当前页面。
- 内容与用途匹配时优先使用现有资源或主题属性，不再建立仅有功能前缀不同的重复资源。确实没有适用资源时，才按项目现有命名和组织方式创建；不通过写死字符串、尺寸或复制图片绕开复用检查。
- 字符串按完整文案核对大小写、标点、空白、换行、格式占位符的类型与索引，不能仅凭含义相近或部分匹配复用；同时检查样式、`formatted`、`translatable` 和已有翻译是否适配用途。不要通过 trim、忽略大小写或修改共享文案强行凑成匹配。
- 图片核对内容、状态、颜色、比例、透明背景和缩放行为；不能只按文件名或大致相似就替换设计素材。
- 尺寸和颜色核对实际值、单位、适配版本和语义用途；相同数值但职责不同的 token 不强行合并。不得为了复用修改共享资源而影响已有页面。
- 交付时简要说明复用了哪些资源、哪些确实需要新增；不能声称检索过未实际检查的模块或资源目录。

## 验证与输出

- 优先使用项目已经配置的检查器和格式化工具；先确认实际任务存在，不假定已安装 ktlint 或 detekt。
- 尽量先检查后修复；格式化仅限授权文件，避免波及无关代码。
- 对命名、类型、默认参数和控制流修改，按风险编译或测试相关模块。
- 分别报告规范检查、编译与行为测试，未执行的验证如实说明；结构校验不能证明业务正确。
- 代码审查给出具体文件、行号、规则来源与最小建议，将编译/行为风险和纯风格意见分开。
- 语法说明给出短小且版本兼容的示例；没有发现问题时明确说明，不为形成报告而制造修改。
- 交付前检查本次临时测试内容的清理状态、资源检索与复用结果，以及新增字符串是否位于对应功能已有字符串下面；仍在等待用户实测的内容单独说明。
