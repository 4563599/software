# kte：逐句解释未提交的修改

读的人是用户本人：他熟悉 Java，不太熟悉 Kotlin，想看懂自己还没提交的改动。他要知道每个文件改了什么、每句代码是什么意思、为什么这样改、用了什么 Kotlin 语法、这些语法和 Java 有什么不同。

格式沿用 lyycode（文件按 git 顺序，每处变更一个代码块，每行后面写意思），区别是：**直接在对话里回答**（不生成网页），**不写「如何验证」**，**导包不显示**，并且对 Kotlin 独有或和 Java 不同的语法**多讲几个小例子**。

这个技能在 Claude Code 和 Codex 里都能用：脚本只需要 Node.js 和 git，下面的路径都是本机的绝对路径。

## 步骤

### 1. 确定要解释哪些文件

用户通常只想看一个或几个文件，不一定是全部修改。

- **用户点名了**类名、文件名、路径或目录（例如「DeviceCaroActivity 和 strings.xml 改的代码」）：只解释这几个，用 `--files` 传给脚本。类名、文件名直接传就行，脚本会在有未提交修改的文件里找。
- **用户没点名**：先运行 `--list` 列出有未提交修改的文件，再问用户要解释哪几个（Claude Code 里可以用多选的选项弹窗，Codex 里直接在对话里问）。只有一个代码文件有修改时，可以直接解释它，不用再问。
- **用户明确说「全部」「所有修改」**：不传 `--files`。
- **用户说「你刚才帮我改的」**：用对话里改过的那几个文件。
- **用户说「暂存区的」「add 过的」**：加 `--staged`，只看已暂存的。

### 2. 导出变更清单

```bash
# 列出有未提交修改的文件（序号、状态、增删行数）
node D:\tools\codex\software\skills\kte\scripts\kte.js --list --repo <仓库>

# 导出这几个文件的变更清单；名字逗号分隔，可以是类名、文件名、相对路径、目录或绝对路径
node D:\tools\codex\software\skills\kte\scripts\kte.js --files DeviceCaroActivity,strings.xml --repo <仓库> [--staged]
```

- 范围默认是已暂存 + 未暂存 + 未跟踪的新文件。脚本把变更清单写到临时目录的 `hunks.md`（不写进仓库），并在终端打印：每个文件的状态、每处变更的类型（i=导包、r=布局/资源、c=代码）、读代码前要留意的问题。
- 名字找不到时，脚本会报错并列出所有有修改的文件，照着列表改名字再跑一次，或者问用户指的是哪个。
- `hunks.md` 里每处变更的标题写着行号范围（例如「新增 第 76–102 行，删除 原第 71–72 行」），回答里的变更标题直接用它。代码块里每行带行号：`+` 和空格开头的是修改后的新行号，`-` 开头的是修改前的旧行号。
- **导包变更（类型 i）在回答里完全不显示**，也不编号、不在统计里提。只看它知道下面用了哪些类就行。新文件开头的 `package` / `import` 脚本已经单独拆成一处导包变更，同样不显示。
- 把 `hunks.md` 从头到尾读完再动笔。只看片段不够时再看完整文件：已暂存的版本用 `git show :<路径>`，改之前的版本用 `git show HEAD:<路径>`，未暂存的修改直接读工作区文件。用 `git grep` 找调用方。
- 脚本提示某个代码文件是「二进制」时，可能被公司加密软件加密了。告诉用户这个文件读不到明文，跳过它。
- 选中的文件里代码变更超过 30 处左右时，先告诉用户数量，问他是一次讲完还是分几次讲，不要自己挑着删减。

### 3. 列出用到的语法

把代码变更里用到的 Kotlin 语法列出来（`?.`、`?:`、`let`、`when`、`companion object`、`suspend` ……），给每个标上类别：Kotlin 独有 / 和 Java 不同 / 和 Java 一样 / Android / 第三方库。回答里**不写文档出处和页码**，用户不需要，所以也不用去查文档。

语法名用 Kotlin 官方文档里的叫法（比如「安全调用 ?.」「Elvis 操作符 ?:」「拖尾 lambda」「伴生对象」）。拿不准叫法时，可以看 lyycode 的速查表 `D:\tools\codex\software\skills\code\references\kotlin-syntax-index.md`。Android 或第三方库的内容（`lifecycleScope`、`LiveData`、DataBinding 生成的属性、Retrofit 注解、`requireContext()` 等）不是 Kotlin 语言本身，标「Android / 第三方库」，用自己的话解释。

### 5. 用 fmt 排好代码块

回答里的代码块会显示在聊天窗口里。窗口不宽，一行太长就会折成两行，代码和说明搅在一起很难看；`diff` 代码块也没有语法高亮。所以所有代码块都用**文件的语言**（Kotlin 文件用 `kotlin`，Java 用 `java`，布局用 `xml`），并且**每行不超过 80 列**（中文算 2 列）。

手工数宽度容易错，用脚本排：把「代码行 ## 说明」交给 `fmt`，它会去掉每行的行号和共同的缩进，把说明对齐，太长放不下的说明改写在代码上一行。

```bash
node D:\tools\codex\software\skills\kte\scripts\kte.js fmt <<'EOF'
===== kotlin
-   71 |         fun start(context : Context){ ## 删除：旧方法头，冒号前多了空格
+   76 |         fun start(context: Context) { ## 方法头不变，只是空格改规范
+   77 |             val legacyIntent = Intent(context, DeviceCaroActivity::class.java) ## 先准备好打开老页面的 Intent
===== kotlin
val name = "Tom" ## 自动推断成 String，相当于 final String
===== java
final String name = "Tom";
EOF
```

- 代码行直接从 `hunks.md` 复制（带不带行号都行），后面加 ` ## 说明`；没有说明的行（花括号、空行、源码里本来就有的注释）不加 `##`。
- 一次回答里的所有代码块（变更代码、语法小课的 Kotlin 和 Java 例子）用 `===== 语言` 分隔，放进同一次 `fmt` 调用，一次排完。输出就是排好的代码块，原样贴进回答。
- 排版规则（脚本已经做好，知道就行）：
  - 改动的代码块每行开头有一列标记：`+` 新增，`-` 删除，空格是没改的上下文。语法小课这种普通代码不加标记列。
  - 说明尽量对齐到同一列；对不齐的写在代码后面空 4 格；还是超过 80 列的，改写在代码上一行，写成 `// ↓ 说明`，表示说明的是下面那行。
  - 行号不再写在每一行里，放到变更标题里（例如「新增 第 76–98 行，删除 原第 71–72 行」）。
- 脚本最后提示「有 N 行超过 80 列」时，是代码本身就太长，不用改代码，照样贴。
- 用户说窗口窄还会折行时，加 `--width 70` 之类再排一次。

- **说到 null、空、默认值时要讲具体**：说明是**哪个变量**为 null、**什么情况下**会是 null（谁调用的、传了什么、哪个条件不满足），以及这时**具体得到什么值**。比如不要写「`readConfig(intent)` 是 null（没传配置）时，用 `EthernetConfig()` 默认值」，要写成：

  > - **代码**：`val config = readConfig(intent) ?: EthernetConfig()`（第 40 行）
  > - **说明**：`readConfig(intent)` 从打开本页的 Intent 里取 `"ethernet_config"`。网络配置页 `NetworkConfigActivity` 里的 `ethernet` 一开始是 null（第 62 行），只有在本页保存过一次后才有值（第 69 行）；SDK 还没接，也读不到充电桩上的配置。所以第一次点进以太网设置时，传过来的就是 null。这时 `?:` 改用 `EthernetConfig()`，也就是开关关闭（`useStaticIp = false`）、IP / 子网掩码 / 网关 / DNS 都是空字符串 `""`。保存过再进来，取到的就是上次保存的值。

  不知道什么情况下会是 null 时，用 `git grep` 找调用方确认；确实找不到的，照实写「什么情况下会是 null 没找到，需要确认」。这条同样适用于「为什么这样改」和代码行后面的说明。
- 把这处变更里用到、值得给不熟悉 Kotlin 的人讲的语法都列出来，越高级的越要讲：空安全、作用域函数、lambda、扩展函数、data class、协程、集合函数等。
- 「Kotlin 独有」指 Java 没有这个语法（例如 `?.`、`?:`、扩展函数、`data class`、作用域函数、拖尾 lambda、`suspend`）；「和 Java 不同」指 Java 有类似的东西但写法或行为不同（例如 `is` 对 `instanceof`、`when` 对 `switch`、`==` 对 `equals`、`companion object` 对 `static`、`val` 对 `final`）。Android / 第三方库的内容标「Android / 第三方库」。
- 语法名用 Kotlin 官方文档里的叫法，比如「安全调用 ?.」「Elvis 操作符 ?:」「拖尾 lambda」「伴生对象」「具名实参」。
- 每处代码变更至少列一个语法；确实没有用到语法的（比如只补了文件末尾的换行），照实写「这处没有用到语法」。

**语法小课（写在对应语法的「说明」下面）**

用户熟悉 Java，只看这段代码里的一处用法，往往还是不明白这个语法一般怎么用。所以「Kotlin 独有」和「和 Java 不同」的语法，各写一段小课：

- 「语法小课」那一行先用一两句话说清这个语法是干什么的、和 Java 差在哪里。
- 下面写 2～3 个**常见的简单例子**，放在 Kotlin 代码块里。例子用日常写法（`name`、`user`、`list` 这类简单名字），不用这次项目里的代码，每个例子能单独编译。每行后面用 `// 说明` 写出结果或意思，比如 `// 输出 5`、`// name 是 null 时得到 "未知"`。
- 能和 Java 对比的，再写一个 Java 代码块，用 Java 实现同样的效果，让用户看到 Kotlin 省掉了什么。Java 没有对应写法的（例如 `suspend`、拖尾 lambda），写「Java 没有对应写法」，再给最接近的 Java 写法（比如回调、匿名内部类、工具类静态方法），并说明差别。
- 小课的代码块也交给 `fmt` 排，每行同样不超过 80 列。
- 例子要短：每个小课的代码加起来一般不超过 15 行。讲一个语法就够，不要顺带讲别的语法；例子里用到别的新语法时，在说明里一句话带过。
- 每个语法在一次回答里只讲一次小课。后面再出现时照常列出标题、代码和说明，小课写「见变更 ① 第 3 条」。

### 7. 读代码时发现的问题

逐句读代码时经常会发现问题，这些对用户最有用。每条都写进顶部的「提醒」，并在对应变更的「为什么这样改」里说明现状：
