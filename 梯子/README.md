# Clash Verge 静态 IP 链式出口配置

把这套方案配置到另一台 Windows 电脑：保留 VPN 原有的节点和分组，在 `AI` 分组选择 `台湾中转→静态IP出口`，让匹配 AI 规则的网站使用固定出口。

本文按 2026-10-25 这台电脑已验证的配置整理。另一台电脑需要自行安装 Clash Verge Rev，并导入自己的有效 VPN 订阅。

## 1. 最终链路

```text
应用 → Clash Verge（127.0.0.1:7897）
     → AI 分组
     → 台湾中转→静态IP出口
     → VPN 中转：悦·🇹🇼台湾2 · A
     → 静态代理：82.26.250.63:7211
     → 目标网站看到的出口：82.26.250.63
```

这里“台湾”指 VPN 中转。网站最终看到的 IP 由静态代理决定，不能据此认定最终出口也在台湾。

| 项目 | 当前设置 |
| --- | --- |
| Clash 工作模式 | 规则模式 |
| Windows 系统代理 | 开启 |
| Clash 混合端口 | `7897` |
| AI 分组当前选择 | `台湾中转→静态IP出口` |
| 内部中转分组 | `AI中转`，默认隐藏 |
| 新配置首选中转 | `悦·🇹🇼台湾2 · A` |
| 静态代理类型 | HTTP 代理，网站仍可使用 HTTPS |
| 静态代理地址 | `82.26.250.63:7211` |
| TUN 模式 | 当前未启用；这套方案通过系统代理工作 |

## 2. 文件说明与账号参数

- [Clash静态IP扩展.完整配置.js](Clash静态IP扩展.完整配置.js)：**推荐另一台电脑使用**，已填写当前静态代理的地址、端口、账号和密码，下载后可直接粘贴到 Clash 全局扩展脚本。
- [Clash静态IP扩展.js](Clash静态IP扩展.js)：保留的空白模板，账号和密码使用占位符，适合以后更换代理参数。
- `Clash静态IP扩展.本机私密.js`：原电脑本地的完整副本，带当前代理参数，可通过自己的 U 盘等方式复制到另一台电脑；此文件已被 Git 忽略，不会随仓库克隆下载。
- [codex-http.example.toml](codex-http.example.toml)：可选的 Codex HTTPS/SSE 配置片段。

本仓库已确认是私有仓库。经账号所有者要求，完整配置已将静态代理账号、密码一并保存并上传；这些参数请仅在自己的电脑和这个私有仓库内使用。若准备公开仓库或转发文件，应先移除登录参数；已提交的凭据仍可能保留在 Git 历史中。

从 GitHub 获取文件时，直接使用上面的“完整配置”即可，无需再次填写账号密码。地址为 `82.26.250.63`，端口为 `7211`；用户名和密码集中保存在完整脚本顶部的 `STATIC_IP` 中。服务商更换参数后，需同步修改该处。

这些文件不包含 VPN 订阅链接和 Codex 登录信息。另一台电脑需导入自己的订阅并登录 Codex。

## 3. 在另一台电脑配置 Clash

1. 安装并打开 **Clash Verge Rev**，导入 VPN 订阅，确认普通 VPN 节点可以正常联网。
2. 确认订阅有名为 `AI` 的代理组。本脚本是在该组基础上添加静态出口；缺少该组时，需先使用含 AI 分组的订阅配置。
3. 在节点列表中确认存在 `悦·🇹🇼台湾2 · A`。如果订阅中的名称不同，把脚本顶部 `PREFERRED_TRANSIT` 改成可用中转节点的完整名称，包括空格和符号。新中转需要能访问静态代理服务器。
4. 打开订阅页的 **全局扩展脚本** 编辑器。已有自己的扩展逻辑时先备份，再合并本脚本；空白脚本可以直接粘贴全文。
5. 推荐直接使用从私有仓库下载的 **`Clash静态IP扩展.完整配置.js`**。也可使用本机私密副本，或自行填好账号、密码后的模板。保存脚本，重新应用当前订阅配置。
6. 设置 **规则模式**，开启 **系统代理**，确认混合端口为 `7897`。若使用其他端口，后续命令中的端口也要相应修改。
7. 打开代理组页面，在 **`AI`** 分组选择 **`台湾中转→静态IP出口`**。
8. 按下一节验证出口，确认通过后再启动 Codex。

脚本保留原订阅中的分组、连接参数和规则，并把静态出口放到 `AI` 选项首位。要恢复原 VPN 出口，在 `AI` 里选原订阅节点或区域分组即可。

### 已有旧配置时的中转选择

脚本把 `悦·🇹🇼台湾2 · A` 放在 `AI中转` 的第一项，作为新安装时的默认值。Clash 可能保留旧配置的分组选择；排序不会覆盖已有选择。

如果此前已经创建过 `AI中转`，可以暂时把脚本中该分组的 `hidden: true` 改为 `hidden: false`，重新应用配置，在 `AI中转` 中手动选 `悦·🇹🇼台湾2 · A`。确认后再恢复隐藏。

## 4. 验证实际出口

在 PowerShell 中执行：

```powershell
curl.exe --proxy http://127.0.0.1:7897 --connect-timeout 8 --max-time 15 https://chatgpt.com/cdn-cgi/trace
```

返回内容中应出现：

```text
ip=82.26.250.63
```

这里特意使用 `chatgpt.com` 测试：该域名会匹配 AI 规则。测试其他 IP 查询网站，可能匹配其他分组，从而看到原 VPN 的 IP。

如果 IP 不对，依次检查：

1. `AI` 是否选中了 `台湾中转→静态IP出口`。
2. 静态代理账号、密码是否填写正确，服务是否仍有效。
3. `AI中转` 是否选中了可用节点，已有旧选择时按上一节处理。
4. 当前规则是否把 `chatgpt.com`、`openai.com`、`oaistatic.com` 和 `oaistatsig.com` 指向 `AI`。本文使用的订阅已包含这些规则；其他订阅需要单独核对。
5. 应用是否仍复用切换前的连接；确认出口后，关闭并重新打开该应用。

## 5. 为什么有些流量走静态 IP，有些没有

有两层设置：应用先选择是否使用代理，进入 Clash 后再按规则选择出口。

| 流量 | 这台电脑的路由 |
| --- | --- |
| 匹配 AI 规则的网站 | `AI` → 静态出口 `82.26.250.63` |
| GitHub | `开发工具` → 原 VPN 节点 |
| 国内网站 | 通常直连，具体取决于订阅规则 |
| 未使用系统代理的命令行程序 | 可能直连，需要单独配置代理 |

选择 AI 静态出口不会把整台电脑所有流量都改成该 IP。要判断某个程序的实际路由，可以在 Clash 的“连接”页面查看域名、规则和代理链。

## 6. Git / Git Bash 的代理配置

Git 不一定读取 Windows 的系统代理。当前仓库曾出现 `errno 10054` 和连接 GitHub 的 `443` 端口超时；为 Git 显式配置 Clash 代理后，拉取成功。

只为当前仓库访问 GitHub 设置代理：

```powershell
git -C C:\github\software config --local http.https://github.com.proxy http://127.0.0.1:7897
git -C C:\github\software ls-remote origin HEAD
git -C C:\github\software pull --ff-only
```

另一台电脑还没有克隆仓库时，可以先为这一次命令指定代理：

```powershell
git -c http.proxy=http://127.0.0.1:7897 clone https://github.com/4563599/software.git C:\github\software
```

仓库需要登录时，使用你自己的 GitHub 账号完成 Git 凭据认证。

取消本仓库的代理设置：

```powershell
git -C C:\github\software config --local --unset http.https://github.com.proxy
```

## 7. 可选：Codex 模型请求改用 HTTPS/SSE

如果 Codex 曾因模型 WebSocket 连接失败反复重连，可以参考 [codex-http.example.toml](codex-http.example.toml)，将片段合并到 `%USERPROFILE%\.codex\config.toml`。

`model_provider = "openai-http"` 要放在 TOML 的顶层区域，通常放在第一个 `[节名]` 之前。已有同名配置时修改现有条目，避免重复定义。保留原文件中的其他设置。

部分旧会话可能保存了原提供商选择。如需同时约束旧会话，可在确认没有其他管理员策略冲突后，用管理员权限创建或合并：

```text
C:\ProgramData\OpenAI\Codex\requirements.toml
```

该文件使用相同的提供商配置内容，属于整台电脑的 Codex 策略。已有该文件时先备份并合并，不能直接覆盖。修改后完整关闭、重新打开 Codex，再检查新日志确认实际传输方式。

此项影响模型请求；启动配置、插件、同步和远程控制可能使用各自的网络连接。HTTPS/SSE 同样需要稳定的代理链路。

官方参考：[配置说明](https://learn.chatgpt.com/docs/config-file/config-reference)、[Windows 管理配置](https://learn.chatgpt.com/docs/enterprise/windows-deployment)。

## 8. 这台电脑的实测记录与排查经验

2026-10-25 使用同一个登录后配置接口进行对照测试：

| 静态出口前的中转 | 完整响应耗时 |
| --- | --- |
| `悦·🇹🇼台湾1 · B` | 一次约 14 秒，多次在 18 秒以上仍未完成 |
| `悦·🇹🇼台湾2 · A` | 约 1.4～2.3 秒 |

当时应用给启动配置请求的超时约为 10 秒，慢中转会触发重试，左侧界面约两分钟后才加载。切换到台湾2 A 后，模型列表接口约 0.9 秒，验证出口仍为 `82.26.250.63`。

这些是当时这台电脑的测量结果。另一台电脑需要复测；节点显示“可用”或延迟很低，不代表较大响应也能及时下载完成。

## 9. 回退

- 临时使用原 VPN：在 `AI` 分组选择原订阅的节点或区域分组。
- 停用链式扩展：恢复之前备份的全局扩展脚本，或在没有其他脚本功能需要保留时清空本脚本，然后重新应用订阅。
- 撤销可选的 Codex HTTP 设置：从用户配置和本次新增的策略文件中移除对应条目，保留其他设置，再重新启动 Codex。

本机私密副本继续被 Git 忽略；已授权上传的完整配置单独保存在私有仓库。更新仓库前可用 `git status` 确认提交内容。
